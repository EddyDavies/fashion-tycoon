# Architecture

## Stack (v1)

- **Framework:** Vite + React 19 + TypeScript
- **Styling:** Tailwind CSS
- **Garment rendering:** SVG technical flats — layered, composited in React
- **State:** React useState / useReducer — no backend, no auth, localStorage for persistence
- **Build:** Vite → static bundle, deployed to Vercel

## Three outputs

Every design session produces three outputs:

| Output | What | When |
|--------|------|------|
| **Technical flat** | Live SVG updating as player designs | Throughout game |
| **AI render** | Lifelike product photo, with/without model | On demand (preview button) + auto at Step 3 end + Step 6 |
| **PDF tech pack** | Manufacturer-ready spec document | On Release (Step 6) |

## SVG system — technical flat

The in-game garment view is a **technical flat**: black outlines on white, no colour fills, varied stroke weights, dashed stitching lines. This is the industry-standard format manufacturers use and expect.

**Stroke hierarchy:**
- Outer silhouette: `stroke-width: 2.5px`
- Interior seams: `stroke-width: 1.5px`
- Construction details: `stroke-width: 1px`
- Stitching: `stroke-dasharray: "3,2"` (dashed)
- Hidden seams: `stroke-dasharray: "1,1"` (dotted)

**Colour in-game:** A separate colour fill layer (semi-transparent, sits behind the outline layer) shows the player's chosen colour. This is stripped to B&W in the PDF export.

**Canvas spec:** `viewBox="0 0 400 560"`. All base and detail SVGs share this coordinate space — alignment is guaranteed by a fixed shared canvas, not runtime positioning.

**Views:** Front and back for each garment. Both rendered in the in-game preview (side by side or toggled). Both included in the PDF tech pack on page 2.

**Layer system:**
```
garment/
  base/         — silhouette SVGs (regular, oversized, boxy) × (hoodie, shirt) × (front, back)
  details/      — toggleable overlay layers, per view:
                  hoodie: hood variants, pocket variants, zipper, drawstrings, embroidery
                  shirt:  sleeve length, collar variant, chest pocket, embroidery
  callouts/     — annotation arrows + measurement markers (PDF only)
```

**SVG source:** Draw from scratch in Figma using Designers Nexus files as reference. Figma exports clean named-layer SVGs; adapting Illustrator AI files produces messy output and is a larger time investment.

## PDF tech pack

Generated by a **Vercel serverless function** using **Browserless.io** (POST HTML → receive PDF). Real Chromium rendering, perfect SVG fidelity.

**Service:** Browserless.io — free tier 1,000 PDFs/month, $9/month beyond.

**Page structure (A4):**
1. Cover — brand name, style, season, garment type, colourway swatch
2. Technical flats — front + back (B&W SVG)
3. Detail callouts — hood, pocket, stitching, hardware specs
4. POM table — Points of Measure (15–20 for shirt, 20+ for hoodie)
5. BOM — fabric, trims, hardware, labels with quantities + Pantone refs
6. Construction notes — stitch types, seam finishes, tolerances

Page count: 4–6 pages (shirt), 8–12 pages (hoodie).

## AI render

API already designed in a separate session (`docs/ai-image-generation.md`). Integration points:
- **Auto-trigger:** end of Step 3 (colour + pattern locked in) and Step 6 (Release)
- **On-demand:** preview button available from Step 2 onwards
- **Variants:** with model / without model (toggle on every render)
- **Interface:** `generateRender(state: DesignState, variant: 'model' | 'flat'): Promise<string>` — returns image URL
- **Stub during build:** returns a placeholder image URL until API is wired

## DesignState shape

Discriminated union on `garmentType` — TypeScript narrows `details` automatically.

```ts
type BaseDesignState = {
  silhouette: 'regular' | 'oversized' | 'boxy'
  material: 'cotton' | 'fleece' | 'technical' | 'denim'
  colour: {
    pattern: 'solid' | 'gradient' | 'stripe' | 'graphic' | 'camo'
    primary: string    // hex
    secondary: string  // hex
  }
  brand: {
    name: string
    identity: 'minimal' | 'bold' | 'streetwear' | 'luxury' | 'utility'
    story: string
  }
}

type HoodieDetails = {
  hood: 'none' | 'standard' | 'oversized'
  pocket: 'none' | 'kangaroo' | 'split'
  zipper: boolean
  drawstrings: boolean
  embroidery: boolean
}

type TshirtDetails = {
  neckline: 'crew' | 'vneck' | 'scoop'
  sleeves: 'short' | 'long' | 'sleeveless'
  hem: 'straight' | 'curved' | 'cropped'
  graphic: boolean
}

type ShirtDetails = {
  sleeve: 'short' | 'long'
  collar: 'standard' | 'band' | 'spread'
  pocket: boolean   // chest patch pocket
  embroidery: boolean
}

type DesignState =
  | (BaseDesignState & { garmentType: 'hoodie'; details: HoodieDetails })
  | (BaseDesignState & { garmentType: 'tshirt'; details: TshirtDetails })
  | (BaseDesignState & { garmentType: 'shirt'; details: ShirtDetails })
```

## Screen flow

```
Garment selector (hoodie vs t-shirt)
  → Step 1: Silhouette
    → Step 2: Material
      → Step 3: Colour & Pattern  [auto AI render trigger]
        → Step 4: Details
          → Step 5: Brand
            → Step 6: Release     [auto AI render trigger + PDF generation]
```

Each step: left panel = choices, right panel = live technical flat.

## Build approach

**Stub-first:** All external interfaces (AI render, PDF) are defined and wired from day one but return mocks. Real API implementations swap in without touching game logic.

```
generateRender()  →  stub returns placeholder PNG
generatePDF()     →  stub returns "PDF coming soon"
```
